# 输送设备缓冲挡块跨产线移交划转系统

## 项目简介

流水线缓冲挡块档案与跨产线移交系统，支持挡块建档、产线树分组、移交划转登记、**移交确认（接收方确认/驳回）**、状态/产线/日期筛选、等待时长与完整流转记录、移交单与确认回执打印、**挡块借用预约**（预约占用、取走登记实际取走人/取走时刻、归还时可改实际归还点、超期未还整行标红、档案占用标记与流转实时对齐）、**挡块盘点差异闭环**（按产线建批次、逐项录入实物、自动标记缺失/错线/重复盘点/盘盈/损坏报废、差异确认与追溯导出）、**班组交班**（一次性登记当班未还预约/待确认移交/待处理盘点差异/拦截中点检工装，接班人逐条确认后交班才完成，交班未完成时禁止新开预约），以及**挡块校准临期提醒**（下次应校日进入 30 天临期窗口即在首页与挡块档案给出临期条数，点开清单核对应校日/所属产线/最近一次校准结论，临期挡块移交须二次确认，不合格挂起不计入临期待办）、**挡块班次点检台账**（按产线筛选在用挡块，逐块登记点检人、班次与是否可用并打卡落库，最近一次点检结论在台账与挡块档案同源展示，刷新或重进页面后条数与列表一致）、**点检工装校准台**（卡尺/塞尺/百分表建台账，登记编号、校准到期日与保管班组；到期未校准或最近校准结论不合格时班次点检打卡统一拦截并逐条列出超期工装编号，校准合格后同一班次再打卡即放行；刷新校准台后超期条数与拦截清单同源一致）。

## 点检工装校准台业务流程

1. **工装台账**：卡尺 / 塞尺 / 百分表逐件建账，登记**工装编号（唯一）、工装类型、校准到期日与保管班组**（可登记规格型号/备注，可停用但台账保留）。
2. **校准登记**：每次校准登记校准日期、结论（合格/不合格）、有效期至、下次应校日期与校准人；**合格时台账“校准到期日”自动同步为本次下次应校日**，工装立即移出拦截清单；不合格不延展到期日，工装按“校准结论不合格”继续拦截。
3. **打卡拦截**：班次点检打卡（含复检打卡）前统一校验全产线共用工装——任一件**到期未校准（到期日早于今天，当天到期不算超期）或最近校准结论不合格**即拦住本次打卡（点检记录不落库），返回专用错误码并**逐条列出超期工装编号、类型、保管班组与拦截原因**；停用工装不拦截。
4. **同班次再打卡**：到工装校准台把超期/不合格工装校准合格后，**同一班次无需换班即可再次打卡并通过**；不合格工装复校合格前持续拦截。
5. **口径一致**：校准台“拦截中（超期/不合格）”条数、编号清单与班次点检打卡拦截明细全部由已落库的工装台账（`gauge_tool`）与校准记录（`gauge_calibration`）实时派生（同一查询口径，不受类型/状态/班组/关键字筛选影响），刷新或重进页面后条数与编号逐条对得上。
6. **交班联动**：当前拦截中的工装随班组交班一次性快照进交班清单（工装编号/类型/保管班组/拦截原因），接班人须逐条确认；仍拦截中的工装须校准合格移出拦截后才能确认，交班中新拦截的工装自动补入交班清单，交班页未确认工装条数与校准台拦截条数同源一致。

## 挡块班次点检业务流程

1. **按产线筛选在用挡块**：在“挡块班次点检”通过产线树筛选（选车间含其下全部产线，不选为全部产线），台账只列当前绑定在产线上的**在用**挡块（挂起待修、未绑定上线的挡块不在点检范围）；可再按最近点检班次、最近结论（可用/不可用/从未点检）、挡块编号/机型关键字过滤。
2. **班次点检打卡**：每块挡块逐块登记**点检人、点检班次（早班/中班/晚班）与本次是否可用（可用/不可用）**，可填点检备注；不可用建议注明异常情况。挂起待修或未绑定产线的挡块后端拒绝打卡。
3. **最近一次点检结论**：台账行实时展示最近一次点检的结论、班次、点检人、打卡时刻（备注悬停可见），不可用整行标红；挡块档案列表与详情展示同一“最近一次点检结论”，详情抽屉可查看该挡块完整点检记录。
4. **口径一致**：点检记录全部落库（`block_inspection`），台账条数（在用/可用/不可用/从未点检）与列表由同一个概览接口、同一份清单实时统计派生，刷新或重进页面后条数与列表保持一致。

## 挡块校准临期提醒业务流程

1. **临期窗口**：以最近一次校准记录的“下次应校日期”为准，距今天不超过 30 天（含当天到期）的在用挡块进入临期窗口，派生状态为 `DUE_SOON` 并计算剩余天数。
2. **条数与清单**：首页“校准临期提醒”与挡块档案顶部均显示临期条数，点击打开同一份待办清单（按应校日升序），可核对每块的下次应校日、所属产线与最近一次校准结论（合格/不合格、校准日期、校准人）。
3. **临期移交二次确认**：临期挡块仍可办理移交，但登记提交前必须二次确认（弹窗明示应校日、剩余天数与最近结论，确认后随单回传 `confirmDueSoon` 标记）；后端强制校验该标记，未确认直接拒绝提交。挂起待修与校准逾期的挡块维持原有禁移交规则不变。
4. **口径一致**：临期条数、清单、档案行内“临期”标记全部由已落库的校准记录与挡块状态实时派生（`GET /api/calibrations/due-soon` 与档案列表同源），挂起待修、已逾期、未校准的挡块不计入临期待办；刷新或重进页面后条数与清单保持一致。

## 班组交班业务流程

1. **发起交班**：交班人在“班组交班”发起登记，系统一次性快照当前全部未结事项作为交班清单：
   - **未还预约**：占用中的借用预约（已预约/已取走/逾时未取，与档案“已约出”同一口径）；
   - **待确认移交**：`PENDING` 状态的移交单；
   - **待处理盘点差异**：盘点中批次的待处理差异（与盘点概览同一口径）；
   - **拦截中点检工装**：校准台当前拦截清单（到期未校准/校准结论不合格，与班次点检打卡拦截同一口径），逐件快照工装编号、类型、保管班组与拦截原因。
   登记前可预览清单内容；没有任何未结事项时无需交班；同一时刻只允许一个交班中的交班单。
2. **接班人逐条确认**：接班人（默认带出登记时的接班人，可改）对清单逐条确认，确认人/确认时间/备注随状态落库；清单为登记时快照不变，同时实时显示源单据当前状态（如预约已归还、移交已确认、工装已移出拦截）供接班人参考。**工装事项须逐条核对工装编号与拦截原因，且仍拦截中的工装须先在工装校准台校准合格（或停用）移出拦截清单后才能确认**；全部事项确认后交班自动完成并记录完成时间。
3. **一致性**：交班单、事项清单、未确认条数全部落库（`shift_handover`/`shift_handover_item`），关闭页面再打开，未确认条数、清单内容与档案占用标记保持一致；交班中单据每次读取时自动与校准台拦截清单对账（交班中新拦截的工装自动补入清单），**未确认工装条数与校准台“拦截中（超期/不合格）”条数同一派生口径，刷新交班页后必然对得上**。
4. **交班未完成禁止新开预约**：存在交班中的交班单（含存在未确认工装）时，借用预约登记被后端拦截并提示剩余未确认条数与拦截中工装件数，预约台按钮同步禁用并显示横幅；交班完成后自动恢复开放。

## 挡块借用预约业务流程

1. **预约**：班组只能预约空闲挡块（在用、未挂起、无占用中预约/待确认移交、校准未逾期）；预约登记即占用，挡块档案列表叠加“已约出”标记（预约单号/班组/约定取用/计划归还/归还点）。
2. **取走**：班组按约取走时登记**取走人与实际取走时刻**（系统自动记时刻），状态变为“已取走”；逾时未取的单也可补登记取走。
3. **归还**：登记归还人与实际归还时刻；**归还点可在登记时修改**（默认沿用约定归还点，改点时约定点与实际点同时写入流转记录可审计），归还后占用解除、档案恢复空闲。
4. **超时提醒（两条线）**：
   - **逾时未取**：过约定取用时间 5 分钟仍未取走，定时任务置为“逾时未取”并落提醒记录，整行标红闪烁；
   - **超期未还**：已取走但过了计划还期仍未归还，列表/档案**实时派生**“超期未还”红标与超期时长，整行标红，首页与预约台顶部显示催还计数。
5. **一致性**：占用状态全部落库，超期标记读取时实时派生（不新增状态）；再进预约台、档案页，占用标记与流转记录始终对得上。取消预约必须填写原因。

## 移交确认业务流程

1. **登记**：移交方在“移交台账管理”登记移交，单据进入 `PENDING` 待确认状态，此时**不**变更挡块产线绑定；同一挡块存在待确认移交单时不可重复登记。
2. **确认/驳回**：接收方在“移交确认”查看挡块规格（机型/厚度/规格模板）、原归属产线、目标产线、移交原因后：
   - 确认接收（必填处理说明）：状态变为 `CONFIRMED`，系统才把挡块当前产线绑定更新为目标产线，可打印确认回执；
   - 驳回（必填驳回说明）：状态变为 `REJECTED`，挡块保留原归属，绑定不变。
3. **筛选与跟踪**：支持按状态、相关产线（移出/移入）、日期区间、挡块编号筛选；待确认单据实时展示等待时长，并**按等待时长排队**（默认“等待最长优先”，可一键切换“等待最短优先”）；等待超过 24 小时的待确认单整行标红并打上“积压过久”醒目标记；详情抽屉展示完整流转记录（登记 → 确认/驳回 → 打印），打开详情再返回列表，排队顺序与标记保持不变。
4. **结果导出**：可将当前筛选结果（含等待时长排序与积压标记）导出为带 BOM 的中文 CSV，Excel 直接打开不乱码。
5. **回执打印**：已确认单据可打印《缓冲挡块跨产线移交确认回执》，回执含确认时间、等待时长、处理说明和流转节点，并记录回执打印次数。

## 挡块盘点差异闭环业务流程

1. **创建批次**：管理员在“挡块盘点差异”按产线（具体产线，车间节点不可盘点）与盘点日期创建批次，批次号 `PD-yyyyMMdd-NNN` 由数据库行锁发号；创建瞬间系统快照该产线当前绑定挡块作为**应盘清单**（口径随后续绑定变化保持不变，可审计），同一产线同时只允许一个盘点中批次。
2. **逐项录入**：扫码/输入挡块编号，录入实物状态（正常/损坏/报废）、现场产线（默认批次产线）、盘点人与现场备注。
3. **自动比对标记差异**：系统对比当前产线绑定与最近移交状态，自动标记
   - **缺失**：应盘未盘到（结束盘点时统一转缺失，也可在待盘行直接确认缺失）；
   - **错线**：当前绑定产线或现场产线与应盘产线不一致（含在其他产线盘到的挡块）；
   - **重复盘点**：同批次同一挡块重复录入（记录重复次数）；
   - **盘盈**：盘到账外/未绑定挡块；
   - **损坏/报废**：实物状态异常。
   最近移交单为“待确认/已驳回”时给出在途/驳回追溯提示。
4. **差异闭环**：差异默认“待处理”，管理员可**确认差异**或**忽略差异**（必填处理人与处理说明）；按差异类型、处理状态、挡块编号筛选；行底色区分待盘/待处理；“详情追溯”抽屉展示盘点明细、完整产线绑定历史、最近移交单与流转记录；盘盈误录可删除。
5. **结束/重开/导出**：存在待处理差异时禁止结束盘点（强制闭环），结束后封账，可重新打开补盘；支持导出带 BOM 的中文 CSV（应盘/绑定/现场、差异类型与处理状态、最近移交追溯等 25 列），Excel 直接打开不乱码。批次、差异状态与处理记录全部落库，页面刷新后保持一致。

> 存量数据库升级：新版后端启动时会在 Web 服务接受请求前自动执行幂等迁移：
> `TransferConfirmSchemaMigration` 补齐 `block_transfer` 的确认字段与状态索引、创建 `transfer_flow_record` 表、
> 将升级前按旧流程登记（无流转记录）的历史单据回填为“已确认”并补登流转记录；
> `TransferSequenceSchemaMigration` 创建 `block_transfer_sequence` 按日期持久化发号器；
> `StocktakeSchemaMigration` 创建 `stocktake_batch`/`stocktake_item`/`stocktake_sequence` 盘点三表并初始化发号锁。
> `BorrowReservationSchemaMigration` 创建 `block_borrow_reservation`/`block_borrow_flow_record`/`block_borrow_sequence` 借用三表，
> 并对 V5 初版库幂等补列 `actual_return_point`（归还时可改归还点）。
> `ShiftHandoverSchemaMigration` 创建 `shift_handover`/`shift_handover_item`/`shift_handover_sequence` 交班三表并初始化发号锁。
> `InspectionSchemaMigration` 创建 `block_inspection` 班次点检记录表（点检人/班次/是否可用/打卡时刻）。
> `GaugeCalibrationSchemaMigration` 创建 `gauge_tool` 点检工装台账表（卡尺/塞尺/百分表编号、校准到期日、保管班组）
> 与 `gauge_calibration` 工装校准记录表（合格/不合格、有效期、下次应校日）。
> 迁移不改动任何 `block_line_binding` 产线绑定，重复启动安全。
> 也可手动执行 `docker/mysql/init/z_V2_transfer_confirm.sql`、`zz_V3_transfer_sequence.sql`
> 、`zzz_V4_stocktake.sql`、`zzzz_V5_borrow_reservation.sql`、`zzzzz_V6_shift_handover.sql`
> 、`zzzzzz_V7_block_inspection.sql` 和 `zzzzzzz_V8_gauge_calibration.sql`（均幂等）。
> 注意：`/docker-entrypoint-initdb.d` 下脚本只在 MySQL 数据目录为空时执行，存量数据卷必须依赖上述启动迁移。

## 技术栈

- 前端：Vue 3、Vite 5、Element Plus、Vue Router、Axios、Day.js
- 后端：Spring Boot 3、JDK 17、Spring Data JPA、Spring Data Redis、Maven
- 数据：MySQL 8、Redis 7
- 部署：Docker Compose、Nginx

## 端口说明

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:3125 或 http://127.0.0.1:3125 |
| 后端 API | http://127.0.0.1:8125/api |
| MySQL | 127.0.0.1:3425 |
| Redis | 127.0.0.1:6425 |

端口来自根目录 `.env`，Docker 端口只绑定 `127.0.0.1`。

## 启动方式

```bash
cd qd-125
docker compose up -d --build
```

本地拆分验证：

```bash
cd backend
mvn compile -q

cd ../frontend
npm ci
npm run build
```

## Docker 构建说明

前端按 `package-lock.json` 执行 `npm ci` 和 `npm run build`；后端使用 Maven 构建；Compose 统一启动 MySQL、Redis、backend、frontend：

```bash
docker compose up -d --build
docker compose ps
```

## 常见问题

- `npm ci` 有 audit 提示不等于构建失败；以 `npm run build` 结果判断构建链路。
- API 报错：先确认后端容器和数据库初始化，再检查 `/api` 代理。
- 镜像拉取失败：调整 `.env` 中 `DOCKER_REGISTRY`。
